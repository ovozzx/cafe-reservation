## 1. 개발 환경 세팅

### Docker

- Homebrew로 Docker Desktop 설치 (`brew install --cask docker`)
- 첫 설치에서 `sudo` 비밀번호가 필요해 실패했지만 `Docker.app`은 이미 `/Applications`에 설치된 상태였음
  → 재설치 시 `It seems there is already an App at '/Applications/Docker.app'` 에러
  → 재설치 없이 `open -a Docker`로 실행하니 정상 동작 (Docker Desktop 4.93.0, CLI 29.8.1)
- `docker-compose.yml`로 MySQL 실행

```bash
docker compose up -d     # 띄우기
docker compose ps        # 상태 확인
docker compose stop      # 멈추기 (데이터 유지)
docker compose down      # 컨테이너 삭제 (볼륨은 유지)
docker compose logs -f   # 로그
```

- Docker Desktop 앱이 켜져 있어야 명령어가 동작함 (재부팅 후엔 앱부터 실행)
- compose 프로젝트명은 **실행한 폴더명**으로 정해짐 → 볼륨 이름도 `{폴더명}_cafe-reservation-data`. 다른 폴더에서 `up` 하면 빈 DB가 새로 생김

### 설정 파일

```
src/main/resources/
├── application.properties        # 공통 (커밋 O)
└── application-local.properties  # DB 접속 정보, JWT secret (커밋 X, .gitignore)
```

```properties
# application.properties
spring.application.name=cafe-reservation
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.profiles.active=local
```

```properties
# application-local.properties
spring.datasource.url=jdbc:mysql://localhost:3309/cafe_reservation?serverTimezone=Asia/Seoul&characterEncoding=UTF-8
spring.datasource.username=ebsoft
spring.datasource.password=ebsoft

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

jwt.secret=(64자 랜덤 Base64 문자열 — 문서에 기록하지 않음)
jwt.access-token-expiration=1800000     # 30분 (ms)
jwt.refresh-token-expiration=604800000  # 7일 (ms)
jwt.issuer=cafe-reservation
```

- `ddl-auto=update` — DB가 비어 있어서 엔티티 기준으로 테이블 자동 생성
- `serverTimezone`, `characterEncoding` — 시간대/한글 깨짐 방지
- `application-local.properties`는 커밋되지 않으므로 **새 환경에서는 직접 만들어야 함**

## 2. Phase 2 (인증) 진행 상황

| 순서 | 작업 | 상태 | 비고 |
|---|---|---|---|
| 1 | Role enum | ✅ | `USER, ADMIN, GUEST` |
| 2 | User 엔티티 | ✅ | `@Getter` + `@NoArgsConstructor(PROTECTED)`, `createGuest()`(전체 UUID), `updateRefreshToken()`, `isGuest()` |
| 3 | UserRepository | ✅ | `JpaRepository<User, String>` |
| 4 | JwtProperties | ✅ | record + `@ConfigurationPropertiesScan`. 미사용 `Component` import만 남음 |
| 5 | JwtTokenProvider | ✅ | AT/RT 생성, `parseClaims`, `validateToken`, `getUserId`, `getRole`(RT면 null) |
| 6 | JwtAuthenticationFilter | ✅ | Bearer 토큰 추출 → 검증 → role 있는 토큰(AT)만 SecurityContext 등록 |
| 7 | SecurityConfig | ✅ | CSRF·세션·폼 로그인 off, URL별 권한, JWT 필터 등록, BCrypt `PasswordEncoder` |
| 8 | AuthService | ⬜ | |
| 9 | AuthController + DTO | ⬜ | |

### 남은 작업

**JwtProperties**
- [ ] 사용하지 않는 `import org.springframework.stereotype.Component;` 삭제

**JwtTokenProvider / Filter — 나중에 고려**
- [ ] RT 생성 시 `.id(UUID.randomUUID().toString())`(jti) 추가 검토 — `iat`/`exp`가 초 단위라 1초 안에 같은 유저 RT를 두 번 만들면 완전히 같은 토큰이 됨 → Rotation 테스트 시 문제
- [ ] AT/RT 구분을 `.claim("type", "access"/"refresh")`로 명시하고 Filter에서 access만 허용 (지금은 "role 유무"로 간접 구분)
- [ ] `resolveToken`의 `substring(7)` → `BEARER_PREFIX` 상수 + `.length()`로 매직 넘버 제거
- [ ] Filter에서 토큰을 3번 파싱(`validateToken`, `getUserId`, `getRole`) → 필요 시 Claims 한 번만 꺼내는 구조로 개선

**SecurityConfig — 나중에 고려**
- [ ] `AuthenticationEntryPoint`(401) / `AccessDeniedHandler`(403) 등록 — 지금은 인증 없이 요청하면 기본값 **403** 응답. 401/403 구분 + `ApiResponse` 형식 통일 (필터 예외는 `GlobalExceptionHandler`가 못 잡음)
- [ ] 앱을 띄워 토큰 없이 인증 필요 URL 호출 → 막히는지 동작 확인

**다음 단계: DTO → AuthService → AuthController** (설계서 4.1)

| 기능 | API | 핵심 |
|---|---|---|
| 회원가입 | `POST /api/auth/register` | 이메일 중복 확인 → `passwordEncoder.encode` 후 저장 |
| 로그인 | `POST /api/auth/login` | `passwordEncoder.matches` → AT + RT 발급, RT는 `updateRefreshToken`으로 DB 저장 |
| 게스트 | `POST /api/auth/guest` | `User.createGuest()` 저장 → **AT만** 발급 |
| 재발급 | `POST /api/auth/refresh` | DB의 RT와 비교 → 일치 시 새 AT + 새 RT (Rotation) |
| 로그아웃 | `POST /api/auth/logout` | `updateRefreshToken(null)` |

- 요청/응답 DTO는 `record` + Bean Validation(`@NotBlank`, `@Email`)
- `UserRepository`에 `findByEmail`, `existsByEmail` 추가 필요
- `ErrorCode`에 인증 관련 코드(이메일 중복, 로그인 실패, 유효하지 않은 RT 등) 확인/추가

## 3. 트러블슈팅

### DataSource 설정 에러

```
Failed to configure a DataSource: 'url' attribute is not specified
and no embedded datasource could be configured.
```

- **원인**: `application-local.properties`가 없었음 (`.gitignore` 대상이라 저장소에 없음) + `local` 프로필 미활성화
- **해결**: `application-local.properties` 생성 + `spring.profiles.active=local` 추가

### UserRepository 컴파일 에러

```
error: illegal start of type
public interface UserRepository extends JpaRepository<User, String>,{
```

- **원인**: 제네릭 뒤에 불필요한 쉼표, `JpaRepository` import 누락
- **해결**: 쉼표 삭제 + `import org.springframework.data.jpa.repository.JpaRepository;`

### JwtProperties 바인딩 실패

```
JwtProperties is annotated with @ConstructorBinding but it is defined as a regular bean
which caused dependency injection to fail.
```

- **원인 1**: record 필드를 괄호가 아닌 body에 `static`으로 선언 → 바인딩 대상이 아님
- **원인 2**: record에 `@Component` → 일반 빈으로 취급되어 생성자 파라미터(`String`, `long`)를 빈에서 찾다가 실패
- **해결**: 필드를 record 괄호 안으로 이동 (`long` 타입), `@Component` 삭제, 메인 클래스에 `@ConfigurationPropertiesScan` 추가
- 자세한 원리: `study.md` → "JwtProperties (@ConfigurationProperties)"

### JwtTokenProvider 컴파일 에러

```
error: ')' expected
    .expiration(New Date(System + jwtProperties.accessTokenExpiration()))
error: missing return statement
```

- **원인**: `New` 대문자 (키워드는 소문자 `new`), `System`은 클래스라 숫자와 더할 수 없음, `Jwts.builder()...compact()` 결과를 반환하지 않음
- **해결**: `new Date(now.getTime() + ...)`, 앞에 `return` 추가
- 그 외: `.subject()` 빈 괄호 → `.subject(userId)`, `.claim("role", role)` → `role.name()`, 접근 제어자 `public` 추가

### validateToken이 false를 반환하지 않음

```java
} catch (Exception e) {
    throw new RuntimeException(e);   // IntelliJ 자동 생성 코드
}
```

- **증상**: 만료된 토큰을 넣으면 `false`가 아니라 `RuntimeException: ExpiredJwtException` 발생 → Filter에서 쓰면 401이 아니라 500
- **원인**: 예외를 잡고 다시 던짐
- **해결**: `catch (JwtException | IllegalArgumentException e) { return false; }` — JWT 관련 예외만 잡아서 코드 버그(NPE 등)는 숨기지 않음

### JwtTokenProvider — Refresh Token을 넣으면 500 에러

```
Authorization: Bearer {Refresh Token}
→ validateToken(RT) = true (같은 키로 서명돼서 통과)
→ getRole(RT) → Role.valueOf(null) → NullPointerException: Name is null
```

- **원인**: RT에는 `role` 클레임이 없는데 `getRole`이 null 체크 없이 `Role.valueOf()` 호출. `valueOf(null)`은 null을 반환하지 않고 **NPE를 던짐**
- **처음 시도 (효과 없음)**: Filter에서 `if (role != null)` — 이미 `getRole` 안에서 예외가 나서 도달 못 함
- **해결**: Provider에서 `return role != null ? Role.valueOf(role) : null;` + Filter에서 `role != null`일 때만 인증 등록
- 자세한 원리: `study.md` → "JwtTokenProvider에서 쓴 문법" (`valueOf()` 입력별 결과, 처음 작성했을 때의 실수)

### JwtAuthenticationFilter — 토큰이 항상 인식되지 않음

```java
bearer.startsWith("bearer")   // 헤더는 "Bearer eyJ..." → 항상 false
```

- **원인**: `startsWith`는 대소문자 구분 + 뒤 공백 누락
- **해결**: `startsWith("Bearer ")` (`substring(7)`도 공백 포함 7글자 기준)
- 자세한 원리: `study.md` → "JwtAuthenticationFilter" (resolveToken)

### JwtAuthenticationFilter 컴파일 에러

```
JwtAuthenticationFilter.java:37: error: illegal start of expression   ← 빈칸 /* ④ */, 만 있음
JwtAuthenticationFilter.java:43: error: illegal start of expression   ← 마지막 인자 뒤 쉼표
```

- **원인 1**: 생성자 인자 자리에 주석만 있고 값이 없음
- **원인 2**: `List.of(...)),` — 마지막 인자 뒤 쉼표 (UserRepository `JpaRepository<User, String>,{`와 같은 종류)
- **원인 3**: `authentication`을 `if (role != null) { }` 안에서 선언했는데 `setAuthentication`은 블록 밖 → 변수 범위 밖 (`cannot find symbol`)
- **해결**: 빈칸 채우기, 쉼표 삭제, `setAuthentication`을 `if` 블록 안으로 이동

### 권한 이름 `"ROLE"` 언더스코어 누락 (컴파일 안 잡힘)

```java
new SimpleGrantedAuthority("ROLE" + role.name())   // → "ROLEGUEST"
```

- **증상(예상)**: 컴파일·실행은 되지만 `hasRole("ADMIN")`이 `"ROLE_ADMIN"`을 찾다가 일치하지 않아 **403**
- **해결**: `"ROLE_" + role.name()`
- 자세한 원리: `study.md` → "JwtAuthenticationFilter" (권한 목록)

### User 엔티티에 `@Data` 사용 (컴파일은 통과)

```java
@Data      // @Getter 대신
@Entity
public class User extends BaseTimeEntity { ... }
```

- **문제**: `@Data` = `@Getter` + `@Setter` + `@ToString` + `@EqualsAndHashCode` + `@RequiredArgsConstructor` → 모든 필드 setter 공개, `toString`으로 password·refreshToken 로그 노출 위험, equals/hashCode 오동작, `public` 기본 생성자
- 컴파일 에러가 안 나서 **문제가 숨어 있음**
- **해결**: `@Getter` + `@NoArgsConstructor(access = AccessLevel.PROTECTED)`, `import lombok.Data` 삭제
- 자세한 원리: `study.md` → "JPA 엔티티 (User)" (엔티티에 `@Data`를 쓰면 안 되는 이유)

### User 컴파일 에러 — 메모 문장이 코드에 들어감

```
User.java:42: error: invalid method declaration; return type required
    updateRefreshToken(), isGuest() 추가
```

- **원인**: 안내 문장을 그대로 붙여넣어 클래스 본문에 코드가 아닌 문장이 들어감
- **해결**: 해당 줄 삭제 후 실제 메서드(`updateRefreshToken(String)`, `isGuest()`) 작성

### 게스트 ID 충돌 가능성 — UUID 앞 8글자만 사용

```java
user.userId = "GUEST_" + UUID.randomUUID().toString().substring(0, 8);
```

- **문제**: 16진수 8자리 = 약 43억 가지. 생일 문제로 게스트 1만 명이면 약 1.2%, 7.7만 명이면 약 50% 확률로 충돌. 직접 할당 PK라 충돌 시 `save()`가 기존 게스트를 덮어쓸(merge) 수 있음
- **해결**: `substring` 제거 → 전체 UUID 사용 (`GUEST_` + 36자 = 42자, `user_id VARCHAR(50)`에 들어감 — 설계서도 "GUEST_{UUID} 형식 수용"으로 50자 설정)
- 설계서 329번째 줄 예시 코드는 아직 `substring(0, 8)` — 맞춰서 수정 필요
